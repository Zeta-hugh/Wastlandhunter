# 锈港下一批执行决定

## 本轮实施与坐标纠正

运行时核查发现：`scene.js` 读取 `data/rustport_scene.json`，尚不读取 TMJ。下方 TMJ 锚点只是编辑地图方案，不能作为当前运行时坐标。实际柳焰为 (420,470)，出生点为 (640,470)，车库为 (900,470)。本轮保持这些实际坐标和故事状态，未修改 TMJ。

已在实际场景加入三块地面区域：连接柳焰与工坊的主路、通向出生点附近的支路、工坊油污作业地；全部复用 QA_PASS 图块。renderer 改为按世界图格绘制，修复旧道路随摄像机移动、覆盖整个视野的问题。区域只定义铺装，不创建墙体碰撞，不声称完成南门或车辆通行设计。

验证：npm test、npm run test:browser、npm run test:renderer:browser 通过；新增相机平移 32 像素时道路屏幕坐标相应变化的回归。实际渲染证据：[铺装小样](../../qa/runtime_previews/rustport_paving_study.png)。此图使用生产 renderer 和 P0 图块，隐藏缺失角色；原有建筑色块仍在，不能当作完整游戏画面或视觉验收通过。下一步仍是五种工坊模块和角色基础帧，TMJ 接入需作为单独的坐标统一任务。

依据本轮实查：manifest 为 11 QA_PASS、615 NEEDS_ART；rustport.tmj 为 64×64 格，只有地面层填满，道路、建筑、屋顶和道具图层均为空。136 张外部 PNG 足够启动素材适配研究，不足以直接交付原创视觉切片。停止无目标扩库，仅在下面的具体缺口无法解决时定向查找。

## 素材采用原则

保留现有 11 项已通过验收的地面、棚布、油桶和首车组件，以其实际像素尺度和 3/4 体积为统一基准。重装机兵提供工业废土造型、道路连接、方向动画的参考，不决定本作故事、城镇布局或主角形象。

| 内容 | 采用决定 | 下一步 |
|---|---|---|
| 地面与道路 | 优先复用本项目 concrete_clean/cracked/oily、ground_dirt_oily_01 | 先用已有资源区分工坊作业地、步行路面与油污；道路缺少有效过渡时才补图 |
| 工坊、围墙、废楼 | MMX 的 mm1_walls、mm1_furnitures、mm1_locate_ruinsbuilding_n_sewer 用作结构参考 | 首批只做墙直段、转角、门框、屋顶边缘、维修台五种原创模块；复用棚布与油桶 |
| 主角、柳焰 | 不用匿名 NPC 换色代替；保留既定身份和造型 | 先按角色合同完成八方向基础帧，再扩展动作；MMX 12 帧表只作动作节奏参考 |
| 普通居民 | NPC 图集可辅助职业轮廓设计 | 工坊修理工优先，其他居民后置；需统一比例、方向和来源条件 |
| Rust Runner | 延续已有底盘、履带、炮塔及 75mm 炮 | 用 MMR 红狼等检查转向/炮管关系，补本车缺失方向；不直接替换成原作知名坦克 |
| 铁牙猎犬 | 独立原创 Boss，不能用原版敌人改名 | 在人物与工坊小样通过后，按现有攻击状态补资产；战场独立验收 |
| 图标、音效、其他城镇 | 暂缓 | 只处理阻碍首段流程的缺项 |

游戏提取图和混合来源工程保持参考状态。明确可复用的资源可适配入库；没有来源依据的图片不自动继承工程代码许可。无须等待所有参考图权属解决，原创组件制作可先推进。

## 自有城镇构图：先做一段，不重排全镇

以下是待落图的局部构图方案，不是已有建筑事实。保留现有锚点：柳焰 (1024,960)、首车触发 (1376,672)、南门 (928,1952)、中央码头灯 (928,864)。坐标均为当前 TMJ 坐标。

- 南门作为进入/出镇的视觉方向；主通路接柳焰附近，再通向东北侧首车工坊。道路表达引导，不增加强制剧情顺序或阵营门槛。
- 工坊入口朝向来路，维修台靠内，战车停放区留足车体及转向空间；棚布、油桶形成正在工作的维修场景，保留首车触发区可达。
- 柳焰附近保留对话空地，屋檐和高物件不得挡住角色脚点；用中央灯作为回程辨识点。
- 诊所、酒馆与港区先保留扩展空间，不凭外部地图批量填建筑；后续按既有任务需求安排服务位置。
- 首个赏金任务遵循既定流程，表现离镇、战斗、返镇反馈；不复制拉多镇或其他原作地图，不移植同人工程任务。

## 最小交付及顺序

1. **地图/Runtime**：沿上述锚点做道路和工坊占地规划；先核对当前投影、触发范围和车辆通行尺度，再修改 TMJ。保持已有 ID 和故事状态。
2. **Art**：五种工坊模块 + 现有地面/道具组装一处小样；主角/柳焰八方向基础帧为启动依赖，同批推进。不生产其他九镇资源。
3. **Contract/QA**：验尺寸、透明边缘、pivot、碰撞及来源；不凭元数据记录把候选标为 QA_PASS。
4. **Mobile/Integration**：实际运行截图检查人物与车的尺度、屋檐遮挡、工坊入口辨识和触屏可达；通过后才扩建港区、诊所、酒馆。
5. **切片闭环**：柳焰 → 修车 → 铁牙猎犬 → 一次领奖 → 保存重载。地图/运行时变化执行 npm test、npm run test:browser 及对应回归；共享构建目录测试串行。

验收重点是“自己的锈港能看懂、能走通”，不是资源数量。当前仅完成核查与采用决定，地图布置和新素材生产尚未执行。

## 节省执行成本

六条分工作为同一代理的检查清单，避免六份重复报告。以此文件为当前决策入口；按一个场景批次交付，更新实际差异和一组证据。不反复跑已通过且不受本轮影响的测试，不进行泛搜索，不为每个小步骤请求确认。
