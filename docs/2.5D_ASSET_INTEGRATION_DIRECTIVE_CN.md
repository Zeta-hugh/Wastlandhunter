# Wasteland Hunter — 2.5D 素材整合规范

本文件是 `docs/WastelandHunter_Codex_Production_Asset_Contract_CN.md` 的视觉整合补充。文件名、尺寸、路径、pivot、metadata 和 QA 流程仍以 Production Asset Contract 为最高规范；本文件规定素材如何组成真实场景。

## 1. 素材不是最终画面

正式场景必须按以下层次组织：

```text
base terrain
→ structural composition
→ material variation
→ functional props
→ storytelling props
→ vegetation
→ decals
→ lighting
→ foreground occlusion
→ ambient effects
```

只把地面、墙、门、箱子和植物摆上地图，不得标记为 `VISUAL_PASS`。

## 2. 统一视觉尺度与透视

- runtime 缩放后的砖块、铆钉、门把手、接缝、人物头部、轮胎和栏杆必须处于同一视觉尺度。
- 环境使用统一 3/4 top-down；ground tile 使用 90° top-down；vertical object、vehicle、character 使用同一 camera language。
- upper-left 为统一主光方向，阴影趋向 lower-right；动态灯光由 renderer 叠加。
- 不合格状态分别标记为 `VISUAL_SCALE_FAIL`、`QA_FAIL_PERSPECTIVE` 或 `QA_FAIL_LIGHTING`，禁止靠任意 resize 伪装通过。

## 3. 接地与 2.5D 图层

每个对象必须定义：

```json
{
  "pivot": [x, y],
  "ground_contact": [x, y],
  "collision_footprint": [width, height],
  "depth_layer": "ground|structure|actor|foreground",
  "z_height": 0
}
```

renderer 通过 `worldY + depth_layer + z_height` 排序。对象可以有动态 contact shadow，但不得把巨大固定阴影烘焙进素材。

推荐绘制顺序：

```text
water / sky
ground / roads / transitions
decals
low props
building foundations
actors and vehicles
walls / roofs / awnings
foreground pipes / railings
smoke / light / weather
UI
```

地图数据继续负责碰撞、入口、NPC 和触发器；视觉对象通过 `asset_binding`、anchor、z_height 和 occlusion metadata 解析，不在地图中写图片路径。

## 4. 建筑与室内

建筑必须由 wall、corner、pillar、door、window、roof、awning、pipe、cable、sign、platform、railing、decal 组合。完整建筑图只能作为概念参考。

可进入建筑必须同时声明：

- exterior footprint
- interior map
- door anchor
- entry spawn
- exit spawn
- roof fade/hide
- foreground wall handling
- interior camera bounds

室内素材必须保持与室外相同的像素密度和 camera language。

## 5. Rustport 材质与变化

优先使用 rusted steel、patched steel、corrugated metal、dirty concrete、old brick、weathered wood、canvas、rubber、oil、dust。避免 clean chrome、glossy sci-fi alloy、bright plastic、perfect glass 和泛滥 neon cyberpunk。

重要区域必须同时有：

- primary：建筑、道路、码头、巨大机械；
- secondary：管道、平台、栏杆、灯、箱子；
- tertiary：裂纹、油污、垃圾、草、线缆、碎石。

重复素材必须有 variation；固定透视的建筑不能用旋转伪造方向。细节优先使用独立 decal：oil、rust、crack、dust、rubble、water stain、tire mark、burn mark。

## 6. 故事与可读性

每个重要区域至少一个 storytelling cluster 和一个视觉 landmark。Rustport 的 landmark 候选包括 harbor crane、hunter bar、water tower、garage、wrecked ship structure。

颜色层级必须服务玩法：

- 环境低饱和；
- 可交互物略高对比；
- 重要 NPC 更清晰；
- 敌人轮廓明显；
- 危险攻击拥有最高视觉优先级；
- loot 可识别但不使用手游式彩色神光。

角色 48×72 runtime 优先保证 head、torso、weapon/tool、hair silhouette 和 direction。柳焰必须保留红发 silhouette，桃夭必须能读出 mechanic identity，林澄必须能读出 medical identity。

## 7. 车辆、武器、Boss 与 FX

11 辆车必须仅靠 silhouette 区分 length、width、track/wheel layout、turret position、armor profile 和 rear structure。75mm、105mm、120mm、machine gun、autocannon、missile 和 SE 必须有独立轮廓。

车辆损伤按 100–70%、70–40%、40–15%、<15%、0% 分级，scratch、smoke、burn、broken armor、sparks、flame 和 destroyed state 都是独立 FX/overlay，不得烘焙进基础 sprite。

每个 Boss 必须有 recognizable silhouette、movement identity、attack identity、weak-point visual、damage state 和 phase visual。muzzle flash、smoke、fire、explosion、electricity、dust 一律使用独立 FX layer。

## 8. 移动端与 LOD

每个视觉验收同时检查 100% runtime scale 和手机实际尺寸。大型对象可以提供 `runtime_full`、`runtime_reduced`，由 AssetRegistry 选择；禁止运行时直接缩放 source master。

## 9. Scene Quality Gate

场景只有在以下全部满足后才能标记 `VISUAL_PASS`：

- perspective consistent
- pixel density consistent
- lighting consistent
- no floating objects
- no obvious tile repetition
- primary landmark exists
- secondary details exist
- tertiary details exist
- storytelling prop exists
- navigation readable
- interactables readable
- mobile screenshot readable
- no promotional-image fragments
- no placeholder production art

任何关键项失败，场景保持未完成状态。
